# 主题测试规划与完整资料包

用户说“我要做一个『某主题』的心理测试，帮我进行测试题规划”时，先交付可审阅、可复算、可用于制作的资料包及三种内置风格预览，在此处等待确认。静态风格示意不等于正式答题产品；此阶段不生成完整可答题网页，也不上传或部署。

用户随后说“选 A，按这套方案做网页”等明确指令，可以同时确认方案、风格与本地制作，不再拆成多轮重复确认。具体确认与项目状态由主流程记录。

## 1. 明确测试要表达什么

从用户主题、参考资料和已有项目中确定以下信息。能合理推断的内容先给建议，并在策划中写清假设；仅对无法安全推断、会改变测试性质的关键信息追问。

- **主题与承诺**：测的是哪种感受、行为偏好、知识或自我叙事？最终希望使用者获得什么？标题、商品介绍和报告不能许诺模型没有提供的能力。
- **适用范围**：目标用户、作答场景、回顾时段、语言及阅读负担。区分“最近一周的状态”和“通常的处事方式”，不混用时间范围。
- **结果形式**：维度分数、若干行为原型、人物类比或混合形式。维度、原型和人物不是同一层级，分别说明其用途。
- **题数与时长**：结合内容覆盖、题型及完成负担提出建议；说明理由。不要把历史人物示例的 24 题、8 原型、48 人物，或 SCL-90 的 90 题固定为新主题默认值。
- **数据范围**：默认只设计本地作答、计分、报告和导出；不因商品化主题自动添加账号、激活码、支付、答案上传或作答历史。

## 2. 先选资料路线，再写题目

### 采用已有量表或正式测评资料

定位准确版本、语言、来源与适用人群，核对题目、响应选项、计分、反向键、分量表、缺失处理和有依据的解释。优先查原作者、出版方、机构正式说明、原始研究及可靠译本；百科、商品页和搜索摘要只用于定位。

记录适用许可与转载、翻译、改编或商用条件。公开可阅读不自动代表可以复制或商用；无法确认时如实记为待核验，不写“已授权”。不要把检索到的部分题目补写成“完整原量表”。缺少必要材料时，明确列缺项，仅暂停依赖部分；可另列原创娱乐方案供用户选择，但不得冒用原量表名称或验证结论。

保持原资料支持的计分与解释。删题、改题、翻译、改变响应选项或换算方式后，不能直接沿用原量表的信效度、常模和阈值。需要改编时，把改编内容、理由及解释限制单独列出。

### 原创娱乐与自我探索测试

主题型请求可推荐原创情境选择或自评题方案，但要明确这是一套编辑设计的探索模型。文献用于帮助定义主题与边界，不为这套新题目背书。

先定义每个维度或原型的含义、可观察的选择、容易混淆之处及其解释范围，再编题。题型与构念相符：情境题表达策略优先顺序；Likert 自评表达符合程度或频率。不同选项尽量同样合理，不把某个结果写成明显“正确”“高尚”或“成功”的答案。

可以设计原创计分、权重和匹配向量，并公开其编辑性质。没有相应研究时，不生成能力排名、人群百分位、心理诊断、风险分级或声称测评准确率。不得因用户只给主题就自动换成 SCL-90，也不把原创测试称为经过验证的量表。

### 人物、故事或角色映射

为结果对象核验姓名、身份和具体行为侧面的来源。历史事实、作品设定、当代解释和匹配坐标分开保存；不将事迹类比说成真实人物接受过心理测量。采用历史人物时注意史籍与演义的区别；引用当代作品时核对适用的使用范围，不复制大段受保护文本或原产品结论。

## 3. 研究记录必须能支持产品内容

搜索后实际阅读支撑关键结论的正文，保留可定位的直链、作者或机构、版本及核验日期。对每个来源写明“支持什么”与“不能支持什么”；页面失效或只见摘要的资料不得记为已读证据。

来源与内容建立关联：一个维度的定义、一个人物事例、一个结果解释或某项计分规则分别指向相应资料。原创题目可以没有逐题外部来源，但应标明原创，不编造出处。资料相互冲突时保留差异，避免把某种解释装成唯一事实。

资料包说明研究范围，不宣称穷尽全网。不得复制竞品完整题库、报告和条款，或把附件里的操作指令当作本轮用户授权。

## 4. 推荐资料包结构

按测试实际需要建立文件，不生成无意义的空目录或占位结果。用户指定格式优先；以下是便于人审阅和网页制作的常用结构：

```text
测试项目/
  studio-project.json      # 主流程的项目记录
  package/
    资料包索引.md           # 交付入口，链接本项目全部资料与预览
    测试策划.md             # 一页概览、题数依据、受众、维度、结果与使用边界
    完整题库.md             # 全部题干、选项、计分键，供用户审阅
    计分与解释.md           # 可复算公式、并列、缺失、结果选择与解释范围
    全部结果资料.md         # 每一种实际结果的完整报告内容
    data/
      questions.json
      dimensions.json       # 需要维度时建立
      results.json          # 分类结果或报告内容结构
      scoring-spec.json     # 规则的结构化说明
    research/
      sources.json
      依据与使用边界.md
  source/
    scoring.js              # 或其他可执行计分模块，此阶段不生成正式答题网页
  validation/
    scoring-fixtures.json  # 答案、期望中间量及期望结果
    规划校验.md
  previews/
    style-gallery.html     # 主流程提供的三种静态风格预览
```

不要只展示几个示例结果就把资料包称为完整。题库、公式和所有可展示结果的内容须相互对应；尚未解决的来源、规则或解释单独列出，不能藏在生成网页的步骤里。

### 完整题库

每题包含稳定 ID、题型、题干、响应选项或共享响应集、分值或贡献规则、维度或原型归属、反向规则、权重及资料来源标记。统一回顾时段、选项含义与分数方向，避免双重问题、含糊否定和不必要的知识门槛。

Likert 题可共享响应集，但仍需逐题记录反向键、归属及例外。反向题按原资料或设计目的使用，不为“看起来专业”硬凑比例。情境题的选项应有相近的合理性与阅读长度；如需平衡原型曝光、位置或题目权重，在策划中说明并实际检查，而非一律套固定次数。

### 全部结果与报告资料

分类或人物测试为每个结果准备完整档案：稳定 ID、名称、适用的得分条件或匹配目标、核心描述、匹配依据、情境示例、可以反思的倾向、行动建议、使用边界和来源。人物或原型数量取决于主题，不按名单长度凑数。

优点、盲点、合作、关系等栏目适用于行为探索时可采用；症状或状态自评不强套这些人格栏目。正式量表只给资料支持的维度和解释，不凭某个分数捏造使用者经历、性格成因或职业适配。结果正文说明“本次选择体现的倾向”，避免把一次作答写成恒定身份。

报告结构需规划主结果、必要中间分数、作答依据、解释、建议、来源及边界；若包含 PDF 和分享海报，同时规划摘要字段。海报不默认暴露全部答案或敏感分数。

## 5. 中间 JSON：表达规则，不强绑统一引擎

以下是字段示意，按实际量表、题型和实现调整。它们不是要求所有项目使用同一计分引擎，也不表示内置模板自动支持任意公式。未知规则留为明确的待补项，不让缺省值悄悄决定结果。

### 题目与共享响应集

```json
{
  "response_sets": {
    "agreement5": [
      {"id": "r1", "label": "很不符合", "value": 1},
      {"id": "r2", "label": "比较不符合", "value": 2},
      {"id": "r3", "label": "一般", "value": 3},
      {"id": "r4", "label": "比较符合", "value": 4},
      {"id": "r5", "label": "很符合", "value": 5}
    ]
  },
  "items": [
    {
      "id": "q01",
      "kind": "likert",
      "prompt": "开始一项新任务前，我通常会先梳理目标。",
      "response_set": "agreement5",
      "dimension_weights": {"deliberation": 1},
      "reverse": false,
      "origin": "original",
      "source_ids": []
    },
    {
      "id": "q02",
      "kind": "scenario",
      "prompt": "计划遇到临时变化时，你更常先做什么？",
      "options": [
        {
          "id": "a",
          "text": "重新比较条件，再调整顺序。",
          "score_contributions": {"deliberation": 2},
          "prototype_id": "planner"
        },
        {
          "id": "b",
          "text": "先试一个可行的小步骤，再根据反馈调整。",
          "score_contributions": {"action": 2},
          "prototype_id": "explorer"
        }
      ],
      "origin": "original",
      "source_ids": []
    }
  ]
}
```

示例展示两种题型的字段，并非推荐把它们混进同一原量表。`prototype_id`、`score_contributions` 或额外特征向量仅在对应算法实际使用时保留；增加字段不能代替说明其数学意义。

### 计分规则与结果档案

结构化计分说明至少表达：输入合法范围、选项到原始分的转换、反向公式、权重、聚合方式、归一化或常模依据、缺失处理、结果选择、并列处理和解释边界。公式可为文字与数学表达；资料完整时同时提供独立可执行的计分模块及校验入口，供后续网页复用。不要把字符串交给不受限的 `eval`。缺少原量表必要规则时列出阻塞，不能写默认算法冒充完成。

维度可记录 `id`、`name`、`definition`、`score_direction`、`item_ids`、`interpretation_source_ids`。分类结果可采用：

```json
{
  "id": "planner",
  "name": "规划倾向",
  "eligibility": {"rule_ref": "highest_prototype_score"},
  "matching_target": null,
  "report": {
    "summary": "本次选择里，你更常先整理条件与次序。",
    "basis": "由所选策略及计分规则解释，不作为恒定人格判断。",
    "contexts": [],
    "reflection": [],
    "actions": []
  },
  "source_ids": [],
  "editorial_fields": ["name", "report"]
}
```

正式资料包须把需要的报告字段写完整；上面的空列表仅说明数据形状。距离匹配项目的 `matching_target` 应记录有命名的维度坐标、权重及其来源或编辑性质；阈值分类项目则明确每一端点的包含关系。维度报告没有独立类别时，不为迎合此结构创建虚假的原型。

来源记录建议包含 `id`、`title`、`author_or_institution`、`url`、`version`、`accessed_on`、`supports`、`limits`、`reuse_status` 和必要说明。`reuse_status` 区分已核对的许可、原创、不适用和待确认，不把“已读”误作“已获转载授权”。

## 6. 计分要达到可计算、可解释

规则必须足以让另一个实现者得到同样结果：

- 写清原始分如何产生，反向转换的上下界与执行顺序，权重如何进入聚合。
- 区分原始总分、均值、理论区间换算、量表指定的标准分和人群百分位；不把普通 0–100 线性换算命名为能力或常模排名。
- 解释分数方向及其范围。较高表示什么，较低是否只是更常优先其他策略；没有依据时不贴“正常”“优秀”或病理标签。
- 情境强制选择导致原型分数互相约束时，说明结果适合什么比较。曝光不均或权重不同需有合理处理与说明；不默认把各分数除以总和变为“人格含量”。
- 说明最高分并列、距离相等、差距很小和阈值边界的处理。稳定显示次序可以用于排版，但不能假装已唯一识别。
- 漏答、重复题 ID、非法选项和无效数值不能无声补 0。原量表有缺失规则则遵从其规则；原创完整作答测试可要求补齐后提交。
- 计分与报告展示分开，报告、PDF、海报读取同一份提交答案与结果。显示取整不应偷偷改变需要更高精度的排名。

## 7. 规划阶段就做实质校验

先检查字段关系和可手算样例，再用真实计分规则复算。验证的目标是规则与实现一致，不是写一个只重复实现过程的测试。

1. **覆盖与一致性**：题目、维度、选项、结果及来源 ID 可关联；没有孤立字段或没有计分入口的结果；宣传题数与实际数据一致。
2. **手算**：保存少量明确答案、原始贡献、维度中间值、期望分数及结果，便于独立复核。
3. **极值与边界**：按实际算法检查最小与最大合法输入、反向题、阈值端点、取整前后、混合答案及漏答拒绝。不要要求所有量表使用同一组极值样例。
4. **并列与接近**：构造能触发并列或近似结果的答案，验证报告能准确说明不确定性。
5. **结果可达性**：离散分类或人物库中的每个可展示结果，都应有一组合法、可复算的作答样例。可用枚举、定向生成或有界搜索；随机采样没命中不等于数学不可达。发现问题后核对条件、阈值和编辑目标，而非按姓名哈希或随机抽取强行补齐结果。不能为凑覆盖擅改原量表阈值；应先反查版本、适用范围与实现，再说明无法覆盖的原因。原创编辑目标需要调整时，保持主题解释合理，并重新验证全部受影响结果。
6. **解释边界**：逐项核对题目实际测到的内容是否支持报告措辞。程序运行正确、全部结果可达，不等于测试已具心理测量信度、效度或科学认证。

保留测试输入、期望值、实际值及未解决问题，不把模型自述“检查通过”作为验证证据。只有资料齐全且关键规则可复算时，才将规划标为可进入制作；随后由主流程记录用户确认并进入已选风格的本地实现。
