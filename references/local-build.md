# 本地网页制作

适用：内容方案、风格和本地制作已经由用户确认，或继续修改现有网页。以 `package/` 中已确认内容为原件；定制评分逻辑时一起更新可执行校验，避免网页另写一套近似规则。

## 从已确认方案开始

1. 读取该项目的资料包索引、完整题库／评分规则、全部结果与验证记录。源文件命名可以按实际项目调整，但在 `package/资料包索引.md` 中列出准确位置。
2. 将用户真实确认写入项目记录。一个用户句子可以确认多个阶段；已有对话授权不因缺少记录而失效。例：

   ```bash
   python3 <SKILL_DIR>/scripts/studio.py record --project <PROJECT> --stage plan --evidence '方案可以，用 B 做网页'
   python3 <SKILL_DIR>/scripts/studio.py record --project <PROJECT> --stage style --style parchment --evidence '方案可以，用 B 做网页'
   python3 <SKILL_DIR>/scripts/studio.py record --project <PROJECT> --stage build --evidence '方案可以，用 B 做网页'
   python3 <SKILL_DIR>/scripts/studio.py prepare-style --project <PROJECT>
   ```

3. 风格资产 `assets/styles/base.css` 和主题 CSS 可供复制或内联；组件以 `.studio-surface` 为根，`<html data-theme="jade|parchment|mist">` 选择主题。首页、题目、报告使用同一视觉语言。参考 `assets/style-gallery/index.html` 的实际组件；自定义参考图可修改样式，保留用户确认的颜色与排版意图。
4. 正式源码放 `source/`，最终可发布文件为 **`site/index.html`**。有构建步骤则同时保存项目内可重复执行的构建入口。最后把 CSS、脚本、数据、必要图片和导出依赖都内联，确保离线可答题，无 CDN／外部字体依赖。不要上传整个源码资料包。

## 默认产品行为

- 首页用准确标题、简明用途、预计用时、题数与“开始测试”。说明结果用于娱乐／自我探索；合法使用的标准化量表则按来源说明用途和边界。不要用“临床级”“精准诊断”等未经证实的文案。
- 每题一个清晰情境，选项单选、键盘可操作、显示第几题和进度。选中后可短暂显示反馈再进入下一题；最后一题由用户点击“生成报告”。返回、修改、重置、切换画面前取消尚未触发的自动跳题，防止连跳和旧事件覆盖新答案。
- 支持上一步、修改答案与重测。默认在本地保存未完成进度，提供“清除本地记录／重新开始”。读取存档时检查题库版本与答案范围；题库更换不能把旧答案错配到新题。无需永久保存可识别个人身份的数据。
- 未答完整不能提交，不把缺答当最低分或 0 分。错误提示指出未完成位置且可跳回。
- 结果由真实作答计算：主类型、次倾向（适用时）、维度分数、解释、优势、常见盲点、关系／行动建议、主题映射与来源说明。量表结果遵循原评分规则；主题角色匹配说明是编辑设定的映射。
- 雷达图／条形图要有维度名、量纲与文本等价内容。百分数须有清楚含义；不要把“画像接近度”伪装成心理测量置信度或全国排名。相同答案与版本应产生相同结果；平局规则必须与资料包一致。
- 手机主操作可轻松点击，字不挤、内容可滚动、焦点可见。为结果导出按钮提供加载与失败反馈，避免连续重复点击。

## PDF 与海报

默认交付两种本地下载：

1. **完整报告 PDF**：中文正常显示，包含本次结果、维度图、主要解释、行动建议和用途说明；多页内容不切断关键文字。可用本地打包的 PDF 库，或把排好版的报告分页渲染为图再封装 PDF。浏览器打印只能作为备用，不替代下载文件。
2. **分享海报 PNG**：包含测试名、主结果、简短解释、核心标签和维度摘要；不暴露完整答案或身份资料。未部署前不虚构二维码／网址；部署后可在用户希望时加入经过验证的正式网址。若生成二维码，实际解码验证目标。

PDF、网页报告和海报都使用**同一次计算的结果快照**，不要各自重算或引用旧结果。导出依赖随站点打包；字体使用本地系统字体或可合法分发的资源。真正在浏览器点击下载，并打开产物检查中文、分页、图表及主结果一致。

## 必做验证

把生成物与验证输出存到项目 `validation/`，不要污染 Skill 本体。选择能发现错误的测试，不以“函数复制一遍算同样值”替代独立预期。

- **计分**：按资料包的手算样例验证极端、混合、反向、加权与平局，核对报告的结果 ID。类型测试验证所有承诺的结果可达；角色映射验证没有重复或遗漏。先通过这些检查再接 UI。
- **真实交互**：走完一整次答题；返回修改至少一题；最后一题返回后重选；快速选择后返回；未完成提交；重测；刷新续答与清除记录。确认一个动作只改变预期的一步。
- **布局**：至少在 320px、390px 手机和桌面宽度检查首页、长题干、最长选项、最后提交与最长报告。检查横向溢出、可点击区域、屏幕底部安全区。Upma 可能有右下角平台标识，主操作优先放左侧或独立行，宽度随可用空间适配；不能为避标识把所有手机按钮固定成同一宽度。
- **导出**：实际下载并检查 PDF 与 PNG，验证中文可读、无空白页／裁切，与当前网页结果一致。只证明 DOM 有按钮不算通过。
- **离线**：断开外部依赖仍可完成答题、计算和导出；控制台无阻断性错误。外链资料可以联网阅读，但不能成为答题运行的依赖。

本地文件可直接打开则提供绝对路径链接并用可用预览工具打开。若浏览器限制下载或字体加载，用仅监听本机的预览服务验证，明确如何打开；不要为本地验收自动发布到第三方。

## 验收与修订

交付本地网页、资料包索引及简明验证结果。列出实测范围和仍需用户判断的内容，不把程序检查说成用户已验收。用户修改内容或风格时只更新相应资料、代码和受影响验证；保留现有项目。

用户表示“网页没问题”等实际验收后记录 `local` 阶段。该记录包含当前站点摘要，方便上线前发现之后是否又被修改。如果当前文件与验收版本不同，核对差异：范围内的排版修复可以验证后继续；内容、计分或结果变化应先让用户审阅受影响部分。不要机械地因每个字节变动重复索取整站批准。

没有部署授权时给出可直接使用的话：**“调用当前 Skill 的部署能力，帮我部署。”** 有当前项目的明确部署授权时，进入 `deployment-upma.md`，不重复要求用户再说一次。
